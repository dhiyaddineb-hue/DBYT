# تنزيل YouTube مع DBYT

يستخدم DBYT `yt-dlp` مباشرةً، ويحاول عملاء YouTube المتاحين بالتتابع. إذا كان عنوان IP الذي ينفذ المهمة محجوبًا من YouTube، يمكن تمرير Proxy اختياري من خلال GitHub Secret باسم `YOUTUBE_PROXIES`.

## إعداد GitHub Secret للـ Proxy

افتح:

`Settings → Secrets and variables → Actions → New repository secret`

ثم أنشئ السر التالي:

- **Name:** `YOUTUBE_PROXIES`
- **Secret:** عنوان Proxy واحد أو عدة عناوين، كل عنوان في سطر مستقل.

أمثلة للقيمة:

```text
socks5h://USER:PASSWORD@HOST:PORT
http://USER:PASSWORD@HOST:PORT
```

يمكن أيضًا استخدام Proxy بلا مصادقة:

```text
socks5h://HOST:PORT
```

لا تستخدم Proxy مجهولًا مع cookies أو أي بيانات شخصية. يمرر DBYT قيمة السر إلى `yt-dlp` في الذاكرة فقط، ولا يكتبها في السجل أو ملفات workspace.

يحاول DBYT كل Proxy بالترتيب، ثم يحاول الاتصال المباشر. داخل كل مسار يجرب عملاء YouTube المتاحين. عند نجاح أحد المسارات يتوقف ويعيد الملف إلى خط الدبلجة. إذا لم تُعرّف `YOUTUBE_PROXIES`، يبقى السلوك اتصالًا مباشرًا فقط.

## fallback اختياري عبر Cobalt مصرح به

إذا كان Proxy غير متاح، يستطيع DBYT استخدام مثيل Cobalt يملك المستخدم حق استعماله. هذا المسار لا يرسل ملف cookies إلى Cobalt، ولا يعمل إلا عند تعريف عنوان المثيل ومفتاحه عبر GitHub Secrets:

| اسم GitHub Secret | القيمة |
|---|---|
| `COBALT_API_URL` | عنوان مثيل Cobalt الذي وافق مالكه على استخدامه، مثل `https://example.example` |
| `COBALT_API_KEY` | API key صادر من مالك المثيل |

لا تضع JWT أو API key في الكود أو في ملف workflow أو في رسالة commit. لا تستخدم `cobalt.tools` أو أي مثيل عام من دون إذن صريح؛ توثيق Cobalt يذكر أن المثيلات المستضافة محمية من الروبوتات وليست مخصصة لاستخدام مشاريع أخرى بلا موافقة. DBYT يرسل المفتاح إلى endpoint Cobalt فقط، ولا يرسله إلى رابط التنزيل الخارجي الذي يعيده المثيل.

## fallback اختياري عبر Invidious-compatible API

يمكن تعريف قائمة مثيلات تثق بها يدويًا عبر السر التالي:

| اسم GitHub Secret | القيمة |
|---|---|
| `INVIDIOUS_INSTANCES` | عناوين HTTPS مفصولة بفواصل أو أسطر، مثل `https://instance.example` |

هذا المسار معطل افتراضيًا عمدًا. المثيلات العامة متغيرة، وقد تحجب API أو تعيد روابط منتهية أو غير صالحة. لا يعتمد DBYT على قائمة عامة ثابتة، ولا يرسل cookies إلى Invidious. استخدم هذا الخيار فقط مع مثيل تديره أو تثق بمالكه.

## ترتيب المحاولات ورسالة الفشل

الترتيب هو `yt-dlp` مع cookies وProxy إن وُجدت، ثم Cobalt المصرح به إن عُرّف، ثم مثيلات Invidious التي عرّفها المستخدم صراحةً. عند فشل جميع المسارات، يتوقف DBYT برسالة تذكر المسارات التي فشلت بدل إخفاء السبب أو الادعاء بأن التنزيل نجح.

لا يضمن Proxy أو Cobalt أو Invidious تجاوز حجب YouTube؛ يجب أن يكون المسار صالحًا، سريعًا بما يكفي لتنزيل ملف الوسائط، ويسمح باتصالات HTTPS طويلة إلى خوادم YouTube و`googlevideo.com`. القوائم العامة المجانية ليست ضمانًا تشغيليًا وقد تسرّب حركة المرور أو تتوقف دون إنذار.
